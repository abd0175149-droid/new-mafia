## 1. الهدف والنطاق

بناء شاشة الملف الشخصي للاعب في تطبيق Flutter بتكافؤ كامل مع صفحة الـ PWA الحالية `/player/profile`. الشاشة هي المركز الشخصي للاعب وتضم:

- **الهوية**: أفاتار قابل للتغيير (اختيار → قص تفاعلي → ضغط → رفع) + اسم قابل للتعديل inline.
- **التقدم التنافسي**: الرتبة (tier) + المستوى (Level) + شريط XP + شريط RR.
- **الإحصاءات**: الأداء العام (مباريات/فوز/خسارة/معدل فوز donut)، إحصاءات إضافية (أطول سلسلة فوز، معدل النجاة، الاتفاقيات)، تحليل الأداء (انقسام الفصائل مافيا/مواطن، donut النجاة، الدور المفضل، نسبة نجاح الديلات).
- **لوحة متصدرين مصغّرة** (أعلى 5).
- **آخر 8 مباريات** مع تفصيل نقاط XP/RR قابل للتوسيع لكل مباراة.
- **إعدادات الحساب**: هاتف مقنّع (قراءة فقط)، إيميل قابل للتعديل/المسح، الجنس، تاريخ الانضمام، تغيير كلمة المرور، رابط تشخيص الإشعارات.
- **مودال دليل نظام التقدم** (XP/Level/RR/الرتب/الديلات) + زر فتح مودال الأدوار (مكوّن خارجي).
- **تسجيل الخروج**.

خارج النطاق: مودال الأدوار نفسه (`RolesInfoModal` → 22-role-cards.md)، شاشة السجل الكامل (16-history.md)، شاشة تشخيص الإشعارات (06-push-notifications.md)، شاشة الرتب الكاملة (15-rank.md).

**لا يوجد أي اعتماد على Socket في هذه الشاشة — REST بالكامل.**

## 4. الواجهة والتجربة تفصيلياً

### 4.0 ثوابت مشتركة للشاشة

**الاتجاه**: كامل الشاشة `RTL` (`Directionality(TextDirection.rtl)`). استثناءان فيزيائيان: زر الترس وشارة الكاميرا مثبّتان على **اليسار الفيزيائي** (في الويب `left-6`/`left-0` تبقى يساراً حتى مع RTL) — في Flutter استخدم `Positioned(left:)` وليس `PositionedDirectional`.

**العمود**: كل المحتوى داخل عمود مركزي بعرض أقصى **512dp** (`max-w-lg`)، حشوة أفقية 16dp (`px-4`؛ الـ hero حشوته 24dp `px-6`)، حشوة سفلية 80dp (`pb-20`)، تباعد رأسي بين البطاقات 20dp (`space-y-5`).

**خلفية**: أسود `#000000`، النص الافتراضي أبيض.

### 4.1 حالة التحميل (Loading)

- شاشة سوداء كاملة، spinner مركزي.
- Spinner: دائرة 48×48dp، حد 4dp لون `#f59e0b` مع الجزء العلوي شفاف، دوران 360° مستمر: **مدة الدورة 2000ms، منحنى linear، لا نهائي**.

### 4.2 حالة الخطأ / غير موجود

- شاشة سوداء كاملة، كتلة نص مركزية، حشوة 32dp.
- رسالة: نص `error` أو fallback حرفي «لم يتم العثور على البروفايل» — لون `#fbbf24`، حجم 20sp، وزن 700، هامش سفلي 16dp.
- الرسائل الممكنة (حرفياً):
  - «لم يتم العثور على حساب» — عند غياب playerId (بدون أي fetch).
  - نص `data.error` من السيرفر أو «خطأ» — فشل منطقي.
  - «خطأ في الاتصال» — فشل شبكة.
- زر «العودة»: حشوة 24×8dp، خلفية `#111827`، حد 1dp `#f59e0b` بشفافية 30%، نص `#fbbf24` حجم 14sp، زوايا 8dp؛ عند الضغط (hover في الويب) خلفية `#f59e0b` بشفافية 10%. الوجهة: شاشة اللاعب الرئيسية (مكافئ `/player` — عبر 08-deeplinks-routing.md).

### 4.3 الشاشة الرئيسية (بعد التحميل)

ترتيب الأقسام من الأعلى للأسفل: Hero → بطاقة تقدم الرتبة → الأداء العام → شبكة الإحصاءات الإضافية → تحليل الأداء → لوحة المتصدرين (شرطية) → زر دليل الأدوار → آخر المباريات (شرطية) → accordion الإعدادات → زر دليل التقدم → زر تسجيل الخروج.

#### 4.3.1 قسم الـ HERO

- **الخلفية**: `linear-gradient(180deg, #0a0500 0%, #000000 100%)` + طبقة overlay بشفافية 20%: `radial-gradient(circle at 50% 30%, {rankColor}44, transparent 50%)`.
- المحتوى مركزي، حشوة: أفقية 24dp، علوية 24dp، سفلية 32dp.
- **زر الترس ⚙️**: مثبّت أعلى-**يسار فيزيائي** (top 24dp, left 24dp)، دائرة 36×36dp، خلفية أبيض 5%، حد 1dp أبيض 10%، الأيقونة emoji ⚙️ بلون `#9ca3af` (يتحول أبيض عند الضغط). الفعل: فتح accordion الإعدادات + بعد **100ms** تمرير سلس للشاشة حتى يتوسط قسم الإعدادات (Flutter: `Scrollable.ensureVisible(alignment: 0.5, duration: ~300ms)` بعد post-frame callback).
- **كتلة الأفاتار**:
  - توهج خلفي: دائرة 144×144dp خلف الأفاتار، `radial-gradient(circle, {rankColor}30, transparent 60%)`، ضبابية blur 25، تكبير scale 1.5.
  - دائرة الأفاتار: **144×144dp** (`w-36 h-36`)، دائرية كاملة، حد **5dp صلب بلون الرتبة**، خلفية `linear-gradient(145deg, #1a1a1a, #0d0d0d)`، ظل ثلاثي: `0 0 40px {rankColor}30`، `0 0 80px {rankColor}10`، داخلي `inset 0 0 20px {rankColor}08`.
  - **أنيميشن دخول**: spring من scale 0 إلى 1، damping 15 (Flutter: `SpringSimulation` أو `flutter_animate` بمنحنى elastic ≈ 600ms).
  - المحتوى: صورة الشبكة `{avatarBaseUrl}{player.avatarUrl}` بـ `BoxFit.cover` إذا `avatarUrl` موجود؛ وإلا emoji fallback بحجم 48sp: **👩 إذا `gender == 'FEMALE'` وإلا 👤**.
  - **طبقة الحفظ**: أثناء أي عملية حفظ (`saving` — مشترك بين حفظ الاسم/الإيميل/الصورة): طبقة سوداء 60% فوق الأفاتار + spinner 24×24dp حد 2dp لون `#fbbf24` (الجزء العلوي شفاف) يدور.
  - **شارة الكاميرا**: دائرة 32×32dp مثبّتة أسفل-**يسار فيزيائي** للأفاتار، خلفية = لون الرتبة، emoji 📷 بحجم 14sp لون أسود، حد 2dp أسود، ظل.
  - **الضغط على الأفاتار أو الشارة** → فتح منتقي الصور (أنواع مسموحة: **JPEG, PNG, WebP** — مكافئ `accept="image/jpeg,image/png,image/webp"`).
- **الاسم**: `h1` بحجم 24sp وزن 900 (font-black)، هامش سفلي 4dp، قابل للنقر (hover يلوّنه `#fde68a`).
  - **وضع التعديل**: عند النقر يتحول إلى حقل نص: خلفية شفافة، حد سفلي 2dp لون `#f59e0b` بشفافية 50%، نص مركزي 24sp وزن 900، عرض 192dp، تركيز تلقائي (+ طلب تركيز صريح بعد 100ms). الحفظ عند **blur أو Enter** (راجع §6.3).
- **شارة الرتبة (pill)**: أنيميشن دخول fade + صعود من y+10، **تأخير 200ms**. صف أفقي inline بمسافة 8dp، حشوة 20×8dp، زوايا كاملة (pill)، خلفية `linear-gradient(135deg, {rankColor}15, {rankColor}05)`، حد 2dp `{rankColor}40`، ظل `0 0 15px {rankColor}10`. المحتوى: أيقونة الرتبة emoji بحجم 20sp + النص الحرفي «{الاسم العربي} {TIER}» (مثال: «مُخبر INFORMANT») بحجم 14sp وزن 700 بلون الرتبة. **ملاحظة bidi**: الاسم العربي أولاً ثم الـ enum اللاتيني — لفّ الـ enum بـ LRM عند الحاجة للحفاظ على الترتيب.
- **صف المستوى + XP** (عرض أقصى 320dp مركزي، مسافة بين العنصرين 12dp):
  - **درع المستوى**: 64×64dp، زوايا 16dp، خلفية `linear-gradient(180deg, {rankColor}25, #0a0a0a)`، حد 2dp `{rankColor}50`، ظل `0 4px 15px {rankColor}15`. داخله عمودياً: نص «LEVEL» بحجم 7sp، uppercase، تباعد أحرف واسع (tracking-widest)، لون `#9ca3af`، وزن 700؛ تحته رقم المستوى بحجم 24sp وزن 900 بلون الرتبة (افتراضي 1).
  - **شريط XP** (يملأ الباقي):
    - صف علوي بحجم 10sp: «التقدم XP» بلون `#6b7280` مقابل «{xp} / {nextLevelXP} XP» بلون الرتبة (افتراضيات: 0 / 500).
    - الشريط: ارتفاع 10dp، خلفية `#1f2937`، زوايا كاملة؛ التعبئة تتحرك من عرض 0 إلى `{xpProgress}%` خلال **1000ms بمنحنى easeOut**، لون التعبئة `linear-gradient(90deg, {rankColor}, {rankColor}88)`.
    - سطر سفلي بحجم 9sp لون `#4b5563`: «المستوى التالي: {nextLevelXP − xp} XP».
- **سنة الانضمام**: «انضم {السنة الميلادية من createdAt}» بحجم 12sp لون `#4b5563`.

#### 4.3.2 بطاقة تقدم الرتبة (RANK PROGRESSION)

حاوية: هامش علوي −4dp (تلتصق بالـ hero)، هامش سفلي 8dp، حشوة أفقية 16dp. أنيميشن: fade + صعود y+10، **تأخير 300ms**. البطاقة: زوايا 16dp، حشوة 16dp، خلفية `linear-gradient(180deg, #111111, #0a0a0a)`، حد 1dp `{rankColor}20`.

- **الجانب الأول (يمين في RTL)**: عنوان «الرتبة الحالية» (14sp وزن 700 لون `#d1d5db`)؛ تحته صف: أيقونة الرتبة 24sp + عمود {اسم الرتبة بلون الرتبة 14sp وزن 700 / «تقدم الرتبة» 10sp لون `#6b7280`}.
- **الجانب الثاني (يسار)**: عنوان «عن الرتب» (نفس نمط العنوان)؛ تحته صف الرتب الخمس بمسافة 8dp، لكل رتبة عمود {أيقونة 24sp / تسمية 7sp}:
  - الرتبة النشطة: opacity كامل + `drop-shadow(0 0 6px {tierColor})` + التسمية بلون الرتبة وزن 700.
  - الرتب السابقة (index أقل من الحالي): opacity 50%.
  - الرتب المستقبلية: opacity 25%، التسمية لون `#4b5563`.
- **شريط RR**: تسمية «{rankRR} / {rrRequired} RR» (10sp لون `#6b7280`؛ افتراضيات 0 / 100)؛ شريط ارتفاع 10dp خلفية `#1f2937`؛ تعبئة متحركة من 0 إلى `(rankRR/rrRequired)×100%` خلال **1000ms**؛ نفس تدرج لون الرتبة.
- سطر مركزي 10sp لون `#4b5563`: «تحتاج {rrRequired − rankRR} RR للترقية».

#### 4.3.3 بطاقة الأداء العام (PERFORMANCE OVERVIEW)

أنيميشن fade، **تأخير 400ms**. بطاقة: زوايا 16dp، حشوة 20dp، خلفية `linear-gradient(180deg, #111111, #0a0a0a)`، حد 1dp `rgba(251,191,36,0.15)`. عنوان «الأداء العام» 14sp وزن 700 لون `#d1d5db`.

صف `justify-around` من 3 أعمدة إحصاء + donut:
1. 🎮 — `stats.totalMatches` — «المباريات» — الرقم أبيض.
2. 🏆 — `stats.totalWins || 0` — «فوز» — الرقم `#34d399`.
3. 💀 — `(totalMatches||0) − (totalWins||0)` — «خسارة» — الرقم `#fb7185`.

(كل عمود: emoji بحجم 24sp، الرقم 24sp وزن 900 بأرقام tabular، التسمية 10sp لون `#6b7280`.)

4. **donut معدل الفوز**: 72×72dp؛ حلقة أساس (track) بسمك 3.5 لون `#1a1a2e`؛ حلقة التقدم بسمك 3.5 لون `#fbbf24` بأطراف مستديرة (`StrokeCap.round`)، زاوية القوس = `winRate/100 × 2π`، تبدأ من الأعلى (الويب يدوّر −90°)، مع توهج `drop-shadow(0 0 4px #fbbf2440)`؛ في المركز «{winRate}%» بلون `#fbbf24` حجم 14sp وزن 900؛ تحت الدائرة «معدل الفوز» بحجم 9sp لون `#6b7280`.
   - (ثابت `97.4` في الويب هو محيط دائرة SVG نصف قطرها 15.5 — لا حاجة له في Flutter؛ استخدم sweepAngle مباشرة.)

#### 4.3.4 شبكة الإحصاءات الإضافية (3 أعمدة، مسافة 8dp)

كل بطاقة: زوايا 12dp، حشوة 12dp، نص مركزي، خلفية `linear-gradient(180deg, #111111, #0a0a0a)`، حد 1dp `rgba(251,191,36,0.12)`. أنيميشن fade + صعود متدرج: **تأخير `100ms×i + 500ms`**. القيمة 20sp وزن 900 tabular، التسمية 9sp لون `#6b7280` بهامش علوي 4dp:

1. `stats.longestWinStreak || 0` — «🔥 أطول سلسلة فوز» — قيمة بلون `#fbbf24`.
2. `{stats.survivalRate}%` — «🛡️ معدل النجاة» — قيمة بلون `#22d3ee`.
3. `{progression.successfulDeals||0}/{progression.totalDeals||0}` — «🤝 الاتفاقيات» — قيمة بلون `#c084fc`.

#### 4.3.5 بطاقة تحليل الأداء (glassmorphism)

أنيميشن fade **تأخير 400ms**. بطاقة: خلفية أبيض 3% (`bg-white/[0.03]` — في Flutter استخدم `Color(0x08FFFFFF)` تقريباً بدل `BackdropFilter` الحقيقي، انظر §13)، حد 1dp أبيض 6%، زوايا 16dp، حشوة 16dp، تباعد داخلي 16dp. عنوان «📊 تحليل الأداء» 14sp وزن 700 لون `#d1d5db`.

- **قسم الديل** (صندوق برتقالي: `#f97316` 5%/10%): «🤝 متى تنجح الاتفاقية؟» 14sp وزن 700 `#fb923c`؛ سطران 11sp لون `#d1d5db`:
  - «✅» + «**ناجحة:** صوّت عليها الأغلبية **و** كان الهدف مافيا فعلاً» (كلمة «ناجحة:» بالأخضر `#4ade80` وزن 700، حرف «و» بوزن 700).
  - «❌» + «**فاشلة:** الهدف كان مواطناً — المبادر يُعاقب بـ **-30 RR** و **-10 XP** ويُقصى هو أيضاً!» («فاشلة:» والقيمتان بالأحمر `#f87171` وزن 700).
- **زر التذييل**: «فهمت! 👍» بعرض كامل، حشوة رأسية 10dp، زوايا 12dp، خلفية `#f59e0b` 10%، حد 20%، نص `#fbbf24` 14sp وزن 700 — يغلق المودال.

#### 4.6 شاشة قص الصورة (ImageCropper) — overlay بملء الشاشة

تُفتح فور اختيار ملف صالح. في Flutter: route/‏overlay بملء الشاشة فوق كل شيء، خلفية `rgba(0,0,0,0.9)`، fade دخول/خروج (≈250ms). (حيل الويب — `<style id="image-cropper-lock">` لتجميد html/body وتعطيل pull-to-refresh، والمستمعون non-passive — **لا تُنقل**: الشاشة في Flutter تملك إيماءاتها طبيعياً.)

- **العنوان**: «📸 تعديل الصورة» — أبيض، وزن 700، 16sp، هامش سفلي 16dp.
- **النص المساعد**: «حرّك الصورة وكبّرها لاختيار المنطقة المطلوبة» — أبيض بشفافية 40%، 12sp، هامش سفلي 12dp.
- **منطقة المعاينة**: حاوية دائرية **280×280dp** (`CANVAS_SIZE = 280`)، قص دائري كامل، حد 3dp `rgba(251,191,36,0.4)`، ظل `0 0 40px rgba(251,191,36,0.1)`، مؤشر grab (سطح مكتب).
  - الرسم (يُعاد عند كل تغيير scale/offset): تعبئة خلفية `#111111` → قص دائري (نصف قطر 140dp من المركز) → رسم الصورة بجودة تنعيم عالية عند الموضع `(offset.x, offset.y)` وبأبعاد `(imgWidth×scale, imgHeight×scale)` → حلقة حدودية بلون `rgba(251,191,36,0.6)` سمك 2dp عند نصف قطر 139dp.
  - **الملاءمة الابتدائية (cover)**: `initialScale = 280 / min(imgWidth, imgHeight)`؛ `offset = ((280 − imgWidth×s)/2, (280 − imgHeight×s)/2)` (توسيط).
- **الإيماءات**:
  - سحب بإصبع/مؤشر واحد: `offset = دلتا الحركة + الموضع عند بداية السحب`. **لا يوجد أي تقييد (clamp) على الإزاحة** — يمكن إخراج الصورة كلياً من الدائرة (سلوك الويب؛ يُحافظ عليه للتكافؤ).
  - pinch بإصبعين: `scale = scaleعند_البداية × (المسافة_الحالية / المسافة_عند_البداية)`، مقيّد **[0.1, 5]**.
  - عجلة الفأرة (desktop/tablet بلوحة مؤشر): خطوة **±0.05** لكل tick، بنفس القيد.
  - في Flutter: `GestureDetector.onScaleStart/Update` يوحّد السحب والقرص (`focalPointDelta` للإزاحة، `details.scale` للتكبير) + `Listener` لأحداث `PointerScrollEvent`.
- **واجهة الزوم** (صف تحت المعاينة، هامش علوي 16dp، مسافة 12dp):
  - زر «−» وزر «+»: دائرتان 36×36dp، حد 1dp أبيض 15%، خلفية أبيض 5%، نص أبيض 18sp وزن 700؛ خطوة **±0.15** بنفس القيد [0.1, 5].
  - بينهما شريط مؤشر: 120×4dp، زوايا 2dp، خلفية أبيض 10%؛ تعبئة `#fbbf24` بعرض `min(100, (scale/3)×100)%` مع transition عرض 100ms.
- **أزرار الإجراء** (هامش علوي 24dp، مسافة 12dp):
  - «إلغاء»: حشوة 10×28dp، زوايا 12dp، حد 1dp أبيض 10%، خلفية أبيض 5%، نص `#999999` وزن 600 حجم 14sp → إغلاق دون رفع.
  - «✓ حفظ الصورة»: نفس الأبعاد، بلا حد، خلفية `linear-gradient(135deg, #fbbf24, #f59e0b)`، نص أسود وزن 700 حجم 14sp.
  - أثناء الحفظ: التسمية «⏳ جاري الحفظ...»، الخلفية `rgba(251,191,36,0.3)`، الزر معطّل.
- **ناتج القص (العقد الحرفي)**:
  - canvas خارجي **`outputSize×outputSize` = 512×512**؛ `ratio = 512 / 280`.
  - رسم الصورة عند `(offset.x×ratio, offset.y×ratio)` بأبعاد `(imgWidth×scale×ratio, imgHeight×scale×ratio)` — **مربع كامل بدون قص دائري** (بطاقة اللعب تعرضها بـ object-cover).
  - ترميز **JPEG بجودة 0.92** → سلسلة base64 بالبادئة الحرفية `data:image/jpeg;base64,`.
  - في Flutter: `PictureRecorder` + `Canvas` → `toImage(512, 512)` → `toByteData(rawRgba)` → ترميز عبر حزمة `image` بـ `encodeJpg(quality: 92)` → base64.

## 5. التكيّف مع الشاشات 6→11 إنش

### compact (أقل من 600dp) — هواتف 6–7 إنش
- عمود واحد كما في الـ PWA حرفياً: سقف عرض المحتوى **512dp** (عملياً أقل من عرض الشاشة فلا يظهر السقف)، حشوة أفقية 16dp (hero: 24dp).

### medium (600–840dp) — تابلت 8 إنش
- سقف عرض العمود يرتفع إلى **640dp** مركزياً؛ كل البطاقات تتمدد لهذا السقف. المحتوى النصي (أسطر المساعدة، سطور الإعدادات) يبقى داخل نفس العمود.

- معاينة القص ترتفع إلى **320dp** — **إلزامي**: تبقى معادلة الناتج `ratio = 512 / previewSize` ويُحسب `initialScale = previewSize / min(w,h)`؛ العقد النهائي (512×512 JPEG q92) لا يتغيّر أبداً.
- مودال الدليل: dialog مركزي 448dp (نفس القيمة). الـ toast يبقى مركزياً بعرضه الطبيعي.

### expanded (أكبر من 840dp) — تابلت 10–11 إنش
- سقف كلي **960dp** مركزي، وتخطيط **two-pane**:
  - **العمود الأيمن (ثابت ≈400dp)**: Hero + بطاقة تقدم الرتبة + الأداء العام + شبكة الإحصاءات الإضافية.
  - **العمود الأيسر (مرن)**: تحليل الأداء + لوحة المتصدرين + زر دليل الأدوار + آخر المباريات + الإعدادات + زر الدليل + تسجيل الخروج.
  - زر الترس يبقى أعلى-يسار الـ hero (داخل العمود الأيمن)؛ التمرير عند فتحه يستهدف accordion الإعدادات في العمود الأيسر (عمودا التمرير مستقلان أو عمود واحد بارتفاع مشترك — اختر عموداً واحداً بتمرير موحّد لتبسيط `ensureVisible`).
- تكبير العناصر الحساسة بدل تمديدها: الأفاتار **176dp** (الحد يبقى 5dp)، donut الفوز **88dp**، donut النجاة **64dp**، درع المستوى **72dp**. أحجام الخطوط تبقى كما هي (المحتوى معلوماتي لا لعبي).
- معاينة القص **360dp** مركزية (بنفس قاعدة `ratio = 512/previewSize`)، وأزرار الإجراء بعرض أقصى 448dp.
- مودال الدليل يبقى 448dp مركزياً (لا يتمدد).

## 6. المنطق والتدفقات

### 6.1 آلة الحالة العامة

```
[دخول الشاشة]
  ├─ لا يوجد playerId في الجلسة → error("لم يتم العثور على حساب")  [بدون أي fetch]
  └─ يوجد → loading
        ├─ GET profile نجح (success=true) → ready  (يبذر nameInput=player.name, emailInput=player.email||'')
        ├─ GET profile فشل منطقياً → error(data.error || "خطأ")
        └─ استثناء شبكة → error("خطأ في الاتصال")
  بالتوازي: GET leaderboard → إن كانت الاستجابة Array: خذ أول 5؛ أي فشل يُتجاهل بصمت (القسم يختفي)
```

حالات فرعية داخل ready (مستقلة): `editingName`، `editingEmail`، `settingsOpen`، `changingPassword` (+`pwMsg`)، `guideOpen`، `rolesModalOpen`، `cropFile` (فتح القص)، `saving` (مشترك)، `saveMsg` (toast)، `expandedMatchIdx` (فهرس أو null).

### 6.2 التحميل وإعادة الجلب
- الجلب يحدث عند كل **دخول للشاشة** (مكافئ mount في Next). في Flutter مع bottom nav يحافظ على الحالة: أعد الجلب عند كل عودة للتبويب (`RouteAware.didPopNext` + عند التبديل للتبويب) لمحاكاة سلوك الصفحة.
- **لا يوجد** polling ولا refetch على visibility في هذه الشاشة (بخلاف شاشة الرتب) — لا تضفه.
- إعادة الاتصال: لا آلية retry تلقائية؛ فشل التحميل الأولي = شاشة الخطأ مع زر «العودة». فشل عمليات الحفظ = toast + استرجاع القيمة (دون فقدان بقية الشاشة).
- استعادة الحالة بعد قتل العملية (Android): إعادة جلب كاملة؛ حالات التحرير غير محفوظة (تكافؤ مقبول).

### 6.3 تعديل الاسم
1. نقر على الاسم → وضع تحرير + تركيز (100ms).
2. عند blur **أو** Enter: `t = trim(nameInput)`.
3. إذا `t` فارغ **أو** يساوي الاسم الحالي → إلغاء صامت: إغلاق التحرير + استرجاع `nameInput = player.name`. (هذا الحارس يمنع الحفظ المزدوج عند Enter ثم blur.)
4. وإلا: `saving = true` (يُظهر spinner فوق الأفاتار) → `PUT /api/player/{id}/profile` بجسم `{"name": t}`.
5. نجاح → تحديث تفاؤلي محلي للاسم + toast «✓ تم حفظ الاسم». فشل منطقي → toast (`d.error` أو «خطأ») + استرجاع القيمة. استثناء → toast «خطأ» + استرجاع.
6. دائماً في النهاية: `saving = false`، إغلاق وضع التحرير.

### 6.4 تعديل الإيميل
- نفس النمط، لكن: إذا `trim(emailInput)` يساوي `(player.email || '')` → إغلاق صامت فقط.
- الجسم: `{"email": t.isEmpty ? null : t}` — **السلسلة الفارغة تمسح الإيميل من السيرفر**؛ عند النجاح محلياً يصبح الإيميل غير معرّف ويعود عرض «إضافة إيميل».
- نجاح → toast «✓ تم حفظ الإيميل»؛ فشل → toast + استرجاع `emailInput = player.email || ''`.

### 6.5 خط أنابيب الأفاتار (كامل)
1. نقر الأفاتار أو 📷 → منتقي صور (معرض) بأنواع JPEG/PNG/WebP.
2. **فحص الحجم**: إذا حجم الملف > `10 × 1024 × 1024` بايت → toast «الصورة كبيرة جداً (أقصى 10MB)» وإنهاء.
3. فتح شاشة القص (فك ترميز الصورة بدقتها الكاملة؛ انظر §13 لسقف الذاكرة).
4. تفاعل المستخدم: pan بلا حدود، zoom مقيّد [0.1, 5] (pinch نسبي / عجلة ±0.05 / أزرار ±0.15).
5. «إلغاء» → إغلاق دون أي رفع. «✓ حفظ الصورة» → توليد الناتج: **مربع 512×512، JPEG جودة 0.92، `ratio = 512/previewSize`، بدون قص دائري**، base64 بالبادئة `data:image/jpeg;base64,`.
6. إغلاق شاشة القص فوراً، ثم `saving = true` → `POST /api/player/{id}/avatar` بجسم `{"image": "<dataURL>"}`.
7. نجاح: `player.avatarUrl = d.avatarUrl + '?t=' + <timestamp ms>` (**cache-buster إلزامي**) + إخلاء الصورة القديمة من كاش Flutter (`imageCache.evict` / cache manager الخاص بـ `cached_network_image`) + toast «✓ تم تحديث الصورة».
8. فشل منطقي: toast (`d.error` أو «خطأ»). استثناء شبكة: toast «خطأ في رفع الصورة».
9. `saving = false`.
10. السماح بإعادة اختيار **نفس الملف** مباشرة (الويب يصفّر `input.value` — في Flutter لا مشكلة أصلاً، لكن لا تمنع التكرار).

### 6.6 تغيير كلمة المرور
1. «حفظ»: تحقق client وحيد — إذا `newPw` فارغة أو طولها < 4 → `pwMsg = "كلمة المرور 4 أحرف على الأقل"` وإيقاف.
2. `POST /api/player-auth/change-password` بجسم `{"currentPassword": currentPw, "newPassword": newPw}` (الحالية تُرسل كما هي — السيرفر يتحقق منها).
3. نجاح: `pwMsg = "✓ تم تغيير كلمة المرور"`، تفريغ الحقلين، وبعد **2000ms** إغلاق النموذج وتفريغ الرسالة.
4. فشل منطقي: `pwMsg = d.error || "خطأ"`. استثناء: `pwMsg = "خطأ في الاتصال"`.
5. «إلغاء»: إغلاق النموذج + تفريغ الحقلين والرسالة.
6. تلوين الرسالة: أخضر إذا احتوت «✓»، وإلا أحمر.

### 6.7 سجل المباريات (accordion)
- فتح أحادي بالفهرس: نقر صف → إن كان مفتوحاً أغلقه (`null`)، وإلا افتحه وأغلق غيره.
- اشتقاق الفوز/الفريق حسب §4.3.8 (breakdown أولاً ثم heuristic قائمة أدوار المافيا).

### 6.8 المؤقتات والمهل (كلها حرفية)
| المؤقت | المدة |
|---|---|
| إخفاء الـ toast | 3000ms |
| إغلاق نموذج كلمة المرور بعد النجاح | 2000ms |
| تأخير تركيز حقل الاسم | 100ms |
| تأخير التمرير إلى الإعدادات بعد زر الترس | 100ms (Flutter: post-frame callback + مدة تمرير ≈300ms) |
| دورة spinner التحميل | 2000ms/دورة |
| تعبئة أشرطة XP/RR | 1000ms |
| transition شريط الزوم | 100ms |

لا توجد أي intervals أو polling في هذه الشاشة.

### 6.9 حالات حدّية إلزامية
- `progression` غائب كلياً → افتراضيات: rankTier=INFORMANT، level=1، xp=0، nextLevelXP=500، xpProgress=0، rankRR=0، rrRequired=100، successfulDeals=0، totalDeals=0.
- `rankTier` غير معروف → INFORMANT.
- `mafiaGames == 0` → عرض الجزء الأحمر من شريط الفصائل 50%.
- `stats.favoriteRole` غائب → إخفاء بطاقة الدور المفضل (بطاقة الاتفاقيات تتمدد وحدها في الشبكة).
- `matchHistory` فارغ/غائب → إخفاء القسم كاملاً (بلا حالة فارغة).
- `leaderboard` ليست Array أو فشل الطلب → إخفاء القسم كاملاً.
- `xpEarned`/`rrChange` غير معرّفين على صف مباراة → إخفاء الـ chips فقط.
- سطر تفصيل بقيمة 0 → يُخفى؛ قوائم تفصيل فارغة → نصا الفراغ؛ **بنود التفصيل تتضمن بند تسوية من السيرفر ليطابق المجموعُ الإجماليَّ** — اعرضها كما تصل.
- `physicalId`/`matchPlayerCount`/`matchDuration`/`matchDate` غائبة → «—».
- الجنس غير FEMALE (بما فيه الغياب) → 👤 و«ذكر».

- بلا معاملات. الاستجابة: **مصفوفة مباشرة** (ليست مغلفة). الحقول المستهلكة لكل عنصر: `id`, `name`, `level`, `rankRR`, `rankTier`. تُقص إلى 5. أي شكل آخر → تجاهل صامت.

### 7.3 `PUT /api/player/{playerId}/profile`
- الجسم: `{"name": "<string>"}` **أو** `{"email": "<string> | null"}` (حقل واحد في كل طلب).

### 7.4 `POST /api/player/{playerId}/avatar`
- الجسم: `{"image": "data:image/jpeg;base64,<...>"}` — مربع 512×512 JPEG جودة 92.
- الاستجابة: `{"success": bool, "avatarUrl": "/uploads/avatars/12.jpg", "error?": "…"}`.
- **العرض**: `avatarDisplayUrl = {avatarBaseUrl} + avatarUrl + '?t=' + timestamp` — الصور تُخدم من host الـ backend وليس origin الـ API الافتراضي بالضرورة (راجع 03-networking-rest.md).

### 7.5 `POST /api/player-auth/change-password`
- الجسم: `{"currentPassword": "…", "newPassword": "…"}` — منقول حرفياً من مصدر شاشة البروفايل.
- **تعارض عبر الملفات يجب حسمه عند النقل**: نفس الـ endpoint في تدفق التغيير الإجباري (10-login-register.md §7.3) يرسل الحقل باسم `oldPassword`، وعقد الخادم القانوني (تحليل `player-auth.routes.ts`) يتوقع `oldPassword`. أي أن `currentPassword` الذي ترسله شاشة البروفايل غالباً غير مُتحقَّق منه فعلياً على الخادم (علّة ويب موروثة). القرار الموصى به في Flutter: أرسل `oldPassword` (الاسم القانوني) لتعمل الحماية فعلاً، وسجّله انحرافاً واعياً في 92-qa-parity.md.
- الاستجابة: `{"success": bool, "error?": "…"}`.

### 7.6 اشتقاق المصغّرات (`avatarThumb`)
دالة محلية (لا endpoint): regex حرفي `^(.*\/avatars\/)([^/?#.]+)\.[a-zA-Z]+(?:[?#].*)?$` → `{prefix}thumbs/{id}.webp` (مصغّر WebP 192px). رابط غير مطابق → يُعاد كما هو؛ null → null. تُستخدم للأفاتارات الصغيرة (≤48dp) في القوائم مع **fallback للأصل عند فشل التحميل** (`errorWidget`). غير مستخدمة داخل شاشة البروفايل نفسها لكنها جزء من طبقة الأدوات المشتركة (02-models-data-layer.md).

## 10. اختلافات Android / iOS

- **أذونات منتقي الصور**:
  - iOS: عبر `PHPicker` لا حاجة لإذن على iOS 14+؛ أضف `NSPhotoLibraryUsageDescription` في Info.plist احتياطاً للمسارات الأقدم.
  - Android: على 13+ يُستخدم Photo Picker النظامي بلا إذن؛ لما قبله `READ_EXTERNAL_STORAGE` بـ `maxSdkVersion=32`.
- **HEIC على iOS**: صور الكاميرا الافتراضية HEIC وليست ضمن الأنواع المقبولة في الويب (jpeg/png/webp). مرّر `imageQuality: 100` لـ `image_picker` ليعيد ترميزها JPEG قبل دخولها خط الأنابيب — الناتج النهائي JPEG دائماً فلا يتأثر العقد. فحص الـ 10MB يطبَّق على الملف **بعد** هذا التحويل (الملف الذي سنعالجه فعلاً).
- **زر الرجوع (Android)**: يجب أن يغلق بالترتيب: شاشة القص → المودال المفتوح (دليل/أدوار) → ثم يخرج من الشاشة (`PopScope`). على iOS إيماءة swipe-back تُعطَّل داخل شاشة القص حتى لا تتعارض مع سحب الصورة (السحب الأفقي جزء من الـ pan).
- **الـ emoji**: مجموعات أيقونات الرتب (🕵️⚔️🎖️💎👑) والميداليات تختلف بصرياً بين Android وiOS — القرار المركزي (قبول emoji المنصة أو تضمين NotoColorEmoji) في 01-foundation-theme.md، ويسري هنا على كل الأيقونات بما فيها `icon` القادمة من السيرفر في بنود التفصيل.
- **الإدخال الآمن**: حقلا كلمة المرور — على iOS عطّل اقتراح كلمة المرور القوية للحقل الجديد إن سبّب تعارضاً (`autofillHints`); على Android امنع لقطات الشاشة لهذه الشاشة إن كانت سياسة التطبيق تتطلبه (قرار في 05-session-auth.md).
- **مؤشر grab وعجلة الفأرة** في شاشة القص: لا معنى لهما على اللمس — تفعيل مستمع العجلة فقط عند وجود مؤشر (منصات تدعم trackpad/فأرة مثل iPad بلوحة مؤشر وChromebook).

## 13. ملاحظات أداء وأمان

**أداء**
- **فك ترميز صور القص**: ملف 10MB قد يكون 40+ ميغابكسل؛ فك الترميز الكامل قد يستهلك مئات الميغابايت. حدّد بعداً أقصى للفك (مثل 4096px عبر `instantiateImageCodec(targetWidth/Height)`) — أكبر بكثير من دقة الناتج (512) فلا أثر بصرياً، ويمنع OOM على أجهزة Android الضعيفة. أعد حساب معادلات القص ضد أبعاد الصورة **المفكوكة** (وهي مرجع `imgWidth/imgHeight` في كل المعادلات).
- **glassmorphism**: استبدل `BackdropFilter` الحقيقي بحاويات شبه شفافة (`~Color(0x08FFFFFF)`) — الخلفيات شبه سوداء والنتيجة متطابقة بصرياً وأرخص بكثير.
- **كاش الصور**: بدون إخلاء الكاش بعد الرفع ستبقى الصورة القديمة ظاهرة رغم الـ `?t=` إذا أعيد استخدام URL قديم في مكان آخر (القوائم/المصغّرات) — أخلِ الأصل والمصغّر معاً.
- أنيميشنات الدخول تعمل مرة واحدة عند بناء الشاشة — لا تكررها عند setState (استخدم أعلاماً/`Animate` بمفاتيح ثابتة).
- إعادة رسم معاينة القص عند كل حركة: احصر الرسم في `CustomPaint` بـ `RepaintBoundary` ولا تعِد بناء بقية الشاشة.
- حمولة الرفع base64 لصورة 512×512 q92 ≈ 40–200KB — مقبولة؛ لا تضغط أكثر (يكسر التكافؤ).

**أمان**
- التوكن من مخزن الجلسة الآمن (05-session-auth.md)؛ لا يُسجَّل في اللوغات، ولا تُسجَّل كلمات المرور أو أجسام `change-password` إطلاقاً في أي interceptor لوغ (03-networking-rest.md).
- السيرفر يرسل رقم الهاتف كاملاً — الإخفاء `$1****$2` عرضي فقط؛ لا تعرض الرقم الكامل في أي مكان ولا تنسخه للحافظة.
- تسجيل الخروج يجب أن يمسح: التوكن، playerId، أي كاش بروفايل محلي، وكاش الصور الشخصية.
- ناتج القص يُرفع عبر HTTPS فقط (إعداد الـ base URL في 03-networking-rest.md)؛ لا يُحفظ ملف الصورة المؤقت بعد الرفع (احذف ملف المنتقي المؤقت إن أنشئ).
- رسائل خطأ السيرفر العربية تُعرض حرفياً كما تصل — لا ترجمة ولا إعادة صياغة (نبرة مقصودة).
